## 2. Tick semantics the monitor relies on (read from source)

- `tickStream` (ll.131–230): `IDLE→RUNNING`; each tick `iteration += 1`; appends pipeline deltas, caps `packages`/`quality` at 50 (`slice(-50)`); sets `VERIFYING` mid-tick then resolves before `saveStream`.
- Invariant (l.195): `continuous:true` → `DONE` unreachable, `maxIterations` ignored; resolves `RUNNING` + `continuous next <label>` log whether verified or not (ll.203–212).
- `continuous:false`: pass → `DONE` (l.207); fail + `iteration >= maxIterations` → `FAILED` with `max iterations …` error (ll.213–216); fail otherwise → `RUNNING` retry (l.218).
- `stopStream` (ll.256–268): any non-terminal → `FAILED`, `error = "stopped by operator"`, log `stopped by operator`.
- `pauseStream`/`resumeStream` (ll.232–254): `RUNNING|VERIFYING → PAUSED ("paused")`; `PAUSED → RUNNING ("resumed")`.
- Poll-visibility note: stored status post-tick is `RUNNING` (continuous) — `VERIFYING` is observable only on a mid-tick GET race. Monitor MUST accept `VERIFYING` transiently (assert `status ∈ {RUNNING, VERIFYING}`, with `RUNNING` dominant), else flaky on fast ticks.

## 3. Monitor CLI shape (extend branch in place — ponytail)

Current gap (why H10 exists): branch polls 2s until `DONE|FAILED|CANCELLED|timeout` (l.237) and scores via `hv5PassFail` expecting `jobStatus done` — a continuous stream hangs to the 180s timeout and then fails. Keep `--mock` byte-behaviour identical.

Proposed argv (all optional, defaults preserve current behaviour except where noted):

```
--api harvest-stream --live --monitor
  [--maxTicks N]        default 6. Poll at most N ticks, then stop-and-assert path.
  [--stop]              after maxTicks (or N RUNNING ticks), call Stop seam, assert FAILED/"stopped by operator".
  [--continuous=true|false] default true. false = single-shot for FAILED-at-cap pin.
  [--baseUrl URL]       already exists (l.74); prod via HARVEST_BASE_URL env. No change.
```

Procedures:

- **P1 continuous-stop (ticket line 1):** POST `{live:true, continuous:true}` (+cellKey optional) → poll 2s up to `--maxTicks` → assert per §4 → `--stop` (Stop API) → one confirming GET → assert `status==FAILED`, `error~/stopped by operator/` → write `state/harvest-verify/HV10-stream_<id>.json` (+ existing `stream-<id>.json` alias) → **exit 0** on that path. Any other terminal (`DONE`, unexpected `FAILED` pre-stop, timeout) → exit 1.
- **P2 FAILED-at-cap (H8 carry, ticket line 5):** POST `{live:true, continuous:false}` against 0-yield cell/provider state → poll to terminal → assert `FAILED` + `error~/max iterations/i` → exit 0. Live only (unit covers DONE-fallback; H8-final §6b). Same flags with `--continuous=false`, no `--stop`.
- **P3 H3-verify narrow lifecycle (carry):** POST continuous (either) → `pauseStream` seam → assert `PAUSED` → `resumeStream` seam → assert `RUNNING` → proceed to P1 stop or P2 terminal. Smallest form: fold into P1 as pause→resume round-trip before `--stop` (one stream, no extra quota); only split to its own stream if worker finds pause/resume racy mid-tick.

Per-tick asserts (P1, across `--maxTicks` ticks): `status ∈ {RUNNING, VERIFYING}`; `iteration` strictly ↑ vs previous tick; `packages.length` non-decreasing; every `url` in new packages matches `^https?://`; joined `logs` contain Exa/Jina trace markers (worker to quote exact substrings from live logs — ticket requires the trace, source has no provider-name literals at this seam) and `continuous next` markers.

Exit-code semantics: `0` = asserted path reached (P1 stopped-by-operator, P2 max-iterations, P3 pause/resume round-trip); `1` = assertion/transport failure; `2` = argv misuse (keep existing `2` for bad combos). `--mock` untouched, still 3-pass.

## 5. Live-run sequence + throttle budget

- Order (worker session): P2 (cap pin) and P1+P3 (continuous + pause/resume folded) = **2 live streams total**, off-peak, sequential (never parallel — prod KV is shared).
- Budget: `--maxTicks 6` default (P1 ≈ 6 polls × 2s + stop ≈ <60s wall); e2e uses **2 polls** then Stop (≈ <30s). Each tick costs one pipeline run (Exa/Jina quota when providers enabled). No retries on quota errors; a 402/quota refusal is evidence, not a rerun trigger.
- E2E live prod sequence (extends ai-harvest block ll.101–158, which already asserts `continuous:true` from response-or-request and the `continuous — Stop to end` badge): Start-continuous → intercept POST, assert **request** `postDataJSON().continuous === true` (tighten: current spec falls back to response echo, ll.137–144) → 2× GET `RUNNING` → click Stop → assert `FAILED`/`stopped` → assert POST body `continuous:true` recorded in test evidence. Prod run: `PLAYWRIGHT_BASE_URL=https://auditorai-gamma.vercel.app ADMIN_KEY=… npx playwright test -g "ai harvest stream"`.

## 6. Alternatives considered

- **Alt A — chosen:** extend `harvest-stream` branch in place (`--maxTicks`, `--stop`, `--continuous`, stop-assert + exit-0 path). Depth: same interface, more Leverage; Locality: poll/assert/exit logic stays in one module.
- **Alt B — rejected:** separate `harvest-verify-continuous.mjs` fork. Shallow duplication of snapshot/poll/bundle code (~80 lines); fails the deletion test; two adapters over one seam with nothing actually varying except tick-count policy (a flag, not a seam).
- **Alt C — rejected for pins, kept for regression:** prove continuous purely with unit/fake-timer tests. Fine for DONE-fallback (already covers H8 §6b-DONE side) but cannot close the FAILED-at-cap pin — 0-yield is natural only against live quota/off backends — nor the prod Stop path. Unit stays as CI regression; live stays throttled and few.

## 7. Risks

- **Quota spend (Exa/Jina):** each live tick burns provider calls. Mitigate: `--maxTicks 6`, 2-poll e2e, 2 streams total, sequential, off-peak, no reruns on quota refusal. Owner explicitly wants live (no dry-first substitution).
- **Prod KV writes:** live streams persist (`harvest:stream:*`), and ticks run the pipeline (ledger/dedupe/coverage side effects possible). Mitigate: gap-aware (no cellKey) unless P2 needs a 0-yield cell; single stream at a time; stop promptly so continuous loops don't accumulate iterations/packages in prod KV.
- **Mid-tick races:** GET landing on `VERIFYING`, pause arriving mid-tick. Mitigate: accept `VERIFYING` transiently; pause/resume asserts retry one poll before failing.
- **180s-timeout hang preserved:** P1 must break the poll loop on `--maxTicks` BEFORE the timeout arm; worker to confirm the `while(true)` edit keeps the existing timeout as backstop only.
- **Stop-seam uncertainty:** ticket says "`--stop` (or Stop API)" — route shape not confirmed in this read (no route file in scope). Worker to confirm (`POST /api/dev/harvest-stream/:id/stop`? action body?) and use exactly that; no new route.
- **Secrets:** live prod needs real `ADMIN_KEY`. Mitigate: env/keychain only; redact from bundle `meta` and logs (keys never in `state/harvest-verify/*.json`).
