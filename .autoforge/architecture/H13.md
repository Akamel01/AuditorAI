## 2. Alternatives (design-it-twice, condensed)

**A. Per-file try/catch in `loadTicketsFromTree` (recommended).** Loop body `:155-164` wrapped so one bad
file → `console.warn` + `skipped[]` entry; valid tickets still served. Strictness stays in the parsers
(sites 1–3 keep throwing — their interface unchanged); leniency lives only in the loop. Single loop, no
mode flag.

**B. Two-phase strict-lint + lenient-serve (rejected).** Loader gains a `strict?: boolean` param (or a
parallel strict loader for lint). Rejected: boolean-param interface forces every caller/test to know the
mode matrix; two loops duplicate the `readdir→read→parse→dedupe` walk and can drift. A already yields
both properties — strict parsers (lint's test surface) + lenient loop (serve path) — with one loop.

**C. Route-level rescue (rejected).** Catch in `route.ts` and return partial index. Rejected: the route
sits *past* the throw — partial state is already lost; recovering there means re-implementing the loop
behind the wrong seam (locality violation; fix-once lives in the loader).

## 3. Recommendation — smallest correct change (ponytail rung 2: reuse seams)

1. **Loader** (`tickets.ts:144-167`): per-file `try/catch` covering `readFileSync:158` +
   `parseTicketFrontMatter:159` + `ticketFromFields:160` + dup-key `seen` check `:161-162`.
   On catch → `console.warn('[tickets] skip <rel>: <message>')`, push `{file: rel, reason: message}`.
   `loadTicketsFromTree` is called from exactly one site (`:192`), so changing its return to
   `{tickets, skipped}` touches one call site. New type next to `TicketIndex`:
   `SkippedTicket {file: string; reason: string}`.
2. **Index shape**: `TicketIndex` (`ticket-types.ts:36-51`) gains `skipped: SkippedTicket[]`.
   Ship as optional (`skipped?:`) or `buildTicketIndex(tickets, skipped = [])` default so the existing
   `buildTicketIndex([...])` caller (`tests/domain/wayfinder-tickets.test.ts:146`) and `TicketBoard`
   (`ticket-board.tsx:7,36` — reads only `counts`/`maps`) stay green untouched. Invariant preserved:
   `counts.total === tickets.length` (skipped excluded from counts, reported as sibling — silence impossible).
3. **Route** (`route.ts:6-17`): unchanged code — `NextResponse.json(indexWayfinderTickets())` at `:10` now
   serializes `skipped` and returns 200 for bad-ticket cases. `try/catch` + `ENOENT` fallback (`:13-15`)
   stay for truly unexpected failures (permission, OOM). No `serverError` mapping change needed.
4. **Lint** (`scripts/wayfinder-tickets.ts`, new `--lint` flag): calls the same lenient loader, prints
   `<file>: <reason>` per skipped entry to stderr, exits `1` iff `skipped.length > 0`, else `0`.
   Must skip the M-R19 markdown-artifact write (`:27-39`) in lint mode (no side effects in a gate).
   Exit codes: `0` clean (including empty tree — nothing invalid), `1` invalid files, `2` usage/IO error.
   `--json` output gains the `skipped` array so automation can `jq` it.
5. **Gates**: wire `npx tsx scripts/wayfinder-tickets.ts --lint` into `.githooks/pre-commit` (new step
   beside `lint`, fastest-fail ordering per `:7` comment; precedent: `harvest-verify --mock` at `:47`)
   AND `ci.yml` `quality` job after `npm run lint` (`ci.yml:74`) — defense in depth, no new job
   (reuses `tsx`, already in devDeps). Both gates use the same seam, so pre-commit and CI can never disagree.

## 4. Interfaces / boundaries (citations per seam)

| Seam | File:line | Interface (caller must know) | Owner after H13 |
|---|---|---|---|
| Strict parsers | `tickets.ts:44-58`, `:83-100` | throw `Error("<rel>: <cause>")`; `reason` embeds file | unchanged, lint's test surface |
| Lenient loop | `tickets.ts:144-167` | returns `{tickets, skipped}`; warns per skip; first-wins on dup (deterministic: maps sorted `:138-141`, names sorted `:151`) | only place that catches |
| Index | `ticket-types.ts:36-51` + `tickets.ts:169-189` | `TicketIndex{…, counts, skipped}`; `counts.total` excludes skipped | additive field only |
| Serve | `route.ts:10` | 200 always (for parse-level faults); `skipped` visible in JSON | no code change |
| Lint | `scripts/wayfinder-tickets.ts` `--lint` | exit `0/1/2`; stderr `file: reason` lines | new thin adapter, same loader |
| Gates | `.githooks/pre-commit`, `ci.yml:64-78` | fail fast, same command both places | one-line additions |

Note on "file:line" (H13 acceptance §2): current parsers throw file-level messages with no line numbers;
lint therefore reports `file: reason`, not `file:line`. Accepted deviation — line tracking inside
`parseTicketFrontMatter` is deferred (ponytail: skipped, add when file-level reports prove insufficient).

## 5. Tradeoffs / risks

- **Silent rot vs fail-closed.** Leniency lets a bad ticket linger if the gate is bypassed (`--no-verify`,
  gate added to only one of pre-commit/CI). Mitigation: wire BOTH gates + `skipped` in the 200 payload
  (board/API observers see it; counts never silently shrink).
- **Dup-key semantics** (`:161`). First-wins is deterministic only because enumeration is sorted; second
  file is skipped with reason `duplicate ticket key <map:id>`. Cross-map same `id` is NOT a dup
  (`ticketKey` at `:40-42` scopes by map — preserve). Lint exits 1 on dups so CI blocks shadowing.
- **`console.warn` observability.** Warns surface in server logs, invisible to board users — that is why
  `skipped[]` rides the payload (warn = operator channel, `skipped` = user channel). Tests asserting
  clean stderr should target the loader return value, not warn absence.
- **`serverError` quieting** (`lib/api.ts:118-126`). Bad tickets no longer reach `:121 console.error`;
  the 500 path stays reserved for unexpected faults — intended, not a logging regression.
- **Shape ripple.** Any exhaustive `TicketIndex` constructor or snapshot (board types, e2e fixtures) sees
  one additive optional field — no break; old clients ignore unknown JSON keys.
- **Griller parallel.** Both read-only; no shared mutable state — no conflict.
