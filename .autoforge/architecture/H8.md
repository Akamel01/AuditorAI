# H8 — Continuous-loop design boundaries (architecture report)

Status: proposed (read-only, no source edits). Scope: `src/discovery/harvest-stream.ts` (235 lines) + `workflow/wayfinder/maps/ai-harvest-stream/tickets/H8-continuous-loop.md`.
Dependencies: H7 (agent-reach-search provider, closed) + H11 (runtime secrets UI, closed) supply keys via existing provider seam. H9 (API/UI) and H10 (monitor) out of scope — no changes at their seams.

## 1. Current Module analysis (codebase-design vocabulary)

- **Module**: `src/discovery/harvest-stream.ts` — continuous harvesting state machine (`IDLE → RUNNING → PAUSED → VERIFYING → DONE|FAILED`).
- **Interface** (what callers/tests must know): `HarvestStream` type (lines 13–29), `createStream(cellKey, live)` (46–66), `tickStream(id, store?)` (118–197), `verifyStream` (100–115), `pause/resume/stopStream` (199–235); invariants: `maxIterations: 10`, poll-driven `GET tick` with 1s debounce, `stop → FAILED "stopped by operator"`.
- **Seam**: the module's exported functions + `DataStore` injection (`store?` param, `getDataStore()` default). Callers (H9 API, H10 monitor, tests) cross this one seam; pipeline (`runDiscoveryPipeline`), providers (`listProviderIds/providerEnabled/resolveProvider`), gap derivation (`JUR_MAP/themeFor`) sit behind it as implementation details.
- **Depth**: currently good — small interface, large hidden behavior (ctx build, fixture-vs-live acquireDocs branch, pipeline run, dedupe persist, verify, retry). H8 must preserve depth: add leverage behind the same seam, not a new module.

Current implementation facts (grounding):
- `tickStream` **overwrites** `packages/quality/coverage` each iteration (lines 165–167) and `DONE`s on first verify pass (177–179); `maxIterations` → `FAILED` (180–184).
- `PAUSED|DONE|FAILED` short-circuit (121); `IDLE → RUNNING` promotion (123).
- `dedupeIndex` already persists across iterations (169–171); logs capped at 200 (97); stream index capped at 50 (75), list at 20 (88).
- Query derivation already branches on `cellKey` (142–146): set → single jurisdiction/theme; null → 5 jurisdictions + 3 gap-aware themes.

## 2. Alternatives considered

### A. Chosen: `continuous` flag on the stream (persisted field + param default `true`)
- **Interface** delta: `HarvestStream.continuous: boolean` + `createStream(cellKey, live, continuous = true)`. `tickStream` branches internally: continuous → append + `VERIFYING → RUNNING` (never `DONE`, ignore `maxIterations`); `continuous: false` → legacy path byte-for-byte.
- **Depth**: deepest option — one boolean buys append, rotation, no-DONE behind the existing seam. **Locality**: all change concentrates in the one module; H9/H10/tests keep crossing the same seam. Passes the deletion test (remove the flag and the loop behavior re-scatters across callers/daemon).
- Cost: interface grows by one knob; `DONE`-unreachable becomes an ordering-constraint part of the interface that must be documented + tested.

### B. Rejected: separate loop-driver module (new `continuous-loop.ts` / daemon-only loop over single-shot ticks)
- A **shallow module**: large new seam (its own types, wiring, ownership of append-vs-overwrite) over thin pass-through logic. Fails the deletion test (deleting it removes almost no inherent complexity — it just forwards to `tickStream`).
- Breaks **locality**: package history would live in two places (overwrite in `tickStream`, append in driver); pause/resume/stop ordering constraints would need duplicating or delegating. Violates ponytail (new file, new seam for one caller) and the touches guard (new glob). Daemon keep-alive (`scripts/harvest-stream-daemon.mjs`) stays a follow-up adapter at the existing seam, not this ticket.

### C. Rejected: infinite-`maxIterations` hack (continuous = `maxIterations = Infinity`, keep overwrite)
- Leaks **implementation** into the **interface**: callers must know the magic value; `DONE` stays reachable so every caller must also suppress it — interface complexity ≈ implementation complexity (shallow).
- Preserves the overwrite bug (history loss per iteration, weaker evidence trail) and still needs rotation logic somewhere. No locality gain over A, strictly worse interface.

## 3. Chosen boundaries

1. **Seam unchanged**: all H8 behavior behind the existing `harvest-stream.ts` interface. No new module, no new seam, no H9 (API param/UI button) or H10 (monitor) changes.
2. **`continuous` defaults `true`** per owner decision; `createStream` third param optional so existing call sites/tests compile unchanged (default preserves new behavior only for new streams — legacy streams loaded from store without the field treat as `continuous: false` or migrate-on-load; recommend `?? false` for stored streams to avoid flipping in-flight streams — one-line migration, no schema change).
3. **Rotation source stays inside the implementation**: gap-aware rotation is inherent — pipeline re-derives `gaps_ranked` each run (HV7 evidence); `tickStream` re-derives per-iteration query from the same `harvest.ts` derivation. `cellKey == null` → rotate top-3 gaps (recommend `iteration % 3` over the re-derived ranking, log `continuous next <cellKey>`); set → stick to the cell (existing lines 142–146 path). No new rotation module, no new cross-module import beyond the three already used.
4. **Terminal-state contract**: continuous mode `DONE` unreachable; `VERIFYING` (pass or fail) → `RUNNING` (next gap). `stop → FAILED "stopped by operator"` kept verbatim (no new status this slice). `pause` holds (existing gate line 121 covers `RUNNING|VERIFYING → PAUSED`), `resume` continues iteration count (no reset).
5. **Poll-driven tick unchanged**: `GET /:id` 1s debounce untouched; tab/monitor must stay open; daemon keep-alive explicitly follow-up.

## 4. Acceptance mapping

- **Append-vs-overwrite**: lines 165–166 change from assign to append (`packages = [...packages, ...new].slice(-50)`, same for `quality`), dedupe-guarded via already-persisted `dedupeIndex`. Cap ~50 bounds `DataStore.put` size; pairing invariant (packages/quality grow together per iteration) must hold — append both from the same pipeline `state` in one edit.
- **Rotation source**: inherent re-derivation (see §3.3). `continuous next <cellKey>` log line is the observable proof of rotation; `currentNode`/`coverage` update per iteration as today.
- **`DONE`-unreachable**: continuous branch skips lines 177–184 `DONE|FAILED(maxIterations)` entirely; `maxIterations` ignored (not deleted — still enforced when `continuous: false`).
- **Pause/resume/stop unchanged**: no edits to lines 199–235 except possibly none at all; `stop` while `PAUSED` also yields `FAILED "stopped by operator"` (existing behavior — `stopStream` gates only on `!= DONE && != FAILED`).
- **Single-shot preserved**: `continuous: false` executes the current lines 176–187 path exactly; `harvest-verify` + existing tests unbroken.
- **Poll tick**: no change; doc note about tab-open requirement + daemon follow-up lives in ticket/docs, not code.

## 5. Tradeoffs

- One-knob interface growth (`continuous`) vs a new module: chosen knob — smaller diff, deeper module, one documented invariant (`DONE` unreachable when true).
- Cap ~50 vs unbounded history: bounded store writes and read latency vs truncated evidence trail; 50 ≈ stream-index cap (75) coherence; dedupeIndex (not the arrays) is the correctness guard against re-adding.
- `VERIFYING → RUNNING`-always vs per-iteration verify gate: keeps the loop simple and the monitor seam stable, but a persistently failing `verifyStream` (e.g. `quality_score != 1`) loops forever until operator Stop — accepted per owner (Stop is the exit), must be visible in logs.
- Stored-stream migration (`?? false` vs `?? true`): `false` is safer (never flips an in-flight single-shot stream to infinite); new streams get `true` via default param.

## 6. Risks

1. **Cross-module interaction (named)**: if `gaps_ranked` is not exposed on pipeline `state`, `tickStream` cannot name the rotated gap without importing a gap function from `harvest.ts` — a new cross-module edge at the seam. Mitigation (keeps touches guard): derive rotation display from the already-built `ctx.query` (jurisdictions/themes for this iteration) or `state.coverage`; do not add imports. Flagged as the single most likely reason to breach the glob guard — if unavoidable, return to architect before touching `harvest.ts`/`pipeline.ts`.
2. **Unbounded loop cost**: continuous + live providers (H7/H11 keys) = ongoing provider spend with no self-termination; only operator Stop exits. Monitor (H10) must surface iteration count + spend; out of scope here but operational risk accepted by owner.
3. **Verify semantics drift**: `verifyStream` currently judges cumulative `packages/quality`; with append, one bad early iteration poisons all later verifies (`some(q => quality_score != 1)` never clears). Decide in implementation: verify per-iteration delta vs cumulative — recommend per-iteration verdict for the transition decision while keeping cumulative arrays for evidence; document whichever is chosen (interface invariant).
4. **Store growth**: packages/quality × 50 + logs × 200 per stream; `listStreams` reads up to 20 streams — poll + list under debounce is fine, but daemon follow-up polling headless multiplies writes. Cap enforcement must apply before `saveStream`.
5. **Weak coverage gate**: `verifyStream` coverage check is existence-only demo ceiling (20% noted ponytail, lines 109–113) — continuous mode inherits it; do not tighten in H8 (H9/H10 or later slice).
6. **Fixture-vs-live branch**: `acquireDocs` stub (149–159) only in non-live; continuous fixture loops are cheap, live loops are not — tests must cover both without hitting network (MemoryStore + seed-portals only).

## 7. Touches confirmation

- Implementation restricted to `src/discovery/harvest-stream.ts` + `tests/domain/harvest-stream.test.ts`: **sufficient** provided §6.1 mitigation holds (rotation display derived from `ctx.query`/`state.coverage`, no new imports, no API/UI/monitor edits, stdlib only, no new deps).
- **Flag condition**: any need to import gap-ranking from `harvest.ts`/`pipeline.ts`, add an API param/UI control, or touch `state/discovery-ledger.json` (forbidden per constraints — ledger is never touched by this module) exceeds the guard and must return to architect/planner before proceeding.

## 8. Test strategy (through the existing seam, MemoryStore adapter)

- Continuous 3 ticks: `createStream(null, false, true)` + MemoryStore → tick × 3 → assert packages/quality appended (length grows), status never `DONE`/`FAILED`, `dedupeIndex` persists across iterations, logs contain `continuous next`.
- Single-shot preserved: `createStream(cell, live, false)` → existing DONE path still reachable; `maxIterations` enforced (FAILED at cap).
- Controls unchanged: pause holds tick (no iteration increment), resume continues count, stop → `FAILED "stopped by operator"`.
- Cap: drive > 50 packages (or unit-test the slice) → length ≤ 50, newest retained.
- No network: non-live seed-portals path; live-provider resolution mocked via existing `providerEnabled` seam (H7/H11 keys not required in unit tests).
