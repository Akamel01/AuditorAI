## 1. Per-surface design (every H9 ticket line answered)

### 1a. Route — validation + default (`route.ts:17-32`)

- **Module / seam:** `POST /api/dev/harvest-stream` is the single external seam for
  stream creation. Its **interface** today is `{live, cellKey}` (`route.ts:21`).
- **Change (smallest diff, stays in guard file):**
  - Extend body type: `{live?: boolean; cellKey?: string | null; continuous?: boolean}`.
  - Default rule exactly as ticket: `const continuous = body.continuous !== false;`
    — omitted/`true`/truthy → `true`; only explicit `false` → one-shot/debug.
  - Persist before `saveStream`: `stream.continuous = continuous;` between current
    `route.ts:25` (`status = "RUNNING"`) and `route.ts:26` (`saveStream`).
    Post-creation assignment (not a `createStream` signature change) keeps the touch
    inside the 4-file guard — `src/discovery/harvest-stream.ts` (H8 owner) is **not** edited.
  - Response unchanged in shape: `201 {streamId, stream}` (`route.ts:28`) now with
    `stream.continuous === true` when defaulted/explicit-true.
- **Depth:** interface grows by one optional scalar; all continuous-loop behaviour
  stays behind the existing seam (H8 loop untouched per constraint). **Leverage**:
  every caller/e2e gets continuous semantics for ~2 lines. **Locality**: default rule
  lives in exactly one place (route), not duplicated in client/control.

### 1b. Client — backward-compat (`client.ts:131-133`)

- Current interface: `startHarvestStream(body: {live?: boolean; cellKey?: string | null})`
  (`client.ts:131`).
- **Change:** add optional field only:
  `body: {live?: boolean; cellKey?: string | null; continuous?: boolean}`.
  Optional → existing callers compile; no new module, no new dep (ponytail).
- Do **not** default inside the client (keep the default rule in the route for locality);
  the control passes `continuous: true` explicitly so the e2e POST-body assertion is
  meaningful and `continuous:false` one-shot callers can still opt out.

### 1c. Control — label / badge / footer (`ai-harvest-control.tsx`)

- `start()` body (`control:43-46`): `JSON.stringify({live, cellKey: cellKey || null})`
  → add `continuous: true` explicitly.
- Button label (`control:145`): `{busy ? "Starting…" : "Start"}` →
  `{busy ? "Starting…" : "Start continuous"}`. `data-testid="ai-harvest-start"`
  (`control:143`) unchanged.
- `Stream` type (`control:9-21`): add `continuous?: boolean` — **optional**, not
  `boolean`. Reason: H8 notes old persisted streams lack the field (falsy); a required
  field would lie about the interface and break falsy-safety (risk §4).
- Status line (`control:189-191`): keep `iter {iteration}/{maxIterations} · packages {len}`
  and append continuous suffix. Exact strings per ticket:
  - badge (text only, reuse existing `rounded bg-sunken px-1.5 py-0.5` span idiom,
    no new motion/keyframes per Apple-design): `<span …>continuous</span>`,
    rendered only when truthy: `{!!stream.continuous && (<span …>continuous</span>)}`.
  - status text: `iter N · packages M · continuous — Stop to end` —
    implement as current prefix + `{stream.continuous ? " · continuous — Stop to end" : ""}`
    (or equivalent template). Falsy-safe: legacy streams render the old text, no crash.
- Footer (`control:214-216`): `Model: opencode/gpt-5-nano · Web search via LLM · … · Poll 2s`
  → append `· Reach: Exa+Jina via agent-reach`. Exact ticket string
  `Reach: Exa+Jina via agent-reach` must appear verbatim.
- `Pause/Resume/Stop` (`control:56-84`) and 2s poll (`control:99-100`, `ponytail:` ceiling
  comment kept) unchanged. Reuse `Panel`/`Eyebrow`/pressable `active:scale-[0.98]`
  (`control:118,119,142`); no new components.

## 3. Alternatives, tradeoffs, risks

- **Chosen: optional body flag (`continuous?: boolean`, default true).**
  One scalar on the existing seam; no new route, no new module; backward-compat;
  e2e asserts one field. Depth preserved (small interface, H8 implementation hidden).
- **Alternative A (min 1): separate `POST …/start` endpoint (or `?continuous=1` query)
  for continuous vs one-shot.** Rejected: a new seam with a single adapter
  (hypothetical seam per codebase-design — nothing varies across it yet); two creation
  paths halve locality (default rule + validation duplicated); more e2e/client churn;
  violates ponytail smallest-diff. Revisit only if one-shot and continuous creation
  genuinely diverge (different validation, auth, or budgets).
- **Tradeoffs of default-true:** matches owner decision (Stop-only terminator) and keeps
  the Start path one click; cost is that one-shot/debug now requires explicit
  `continuous:false` knowledge — mitigate by keeping `false` honored in route (§1a)
  and documenting it in the control footer/code comment, not a second button.
- **Risks:**
  - R1 — Old streams without `continuous` (H8 note, falsy): mitigated by optional
    `Stream.continuous?` + truthy-gated badge/suffix (§1c); never `=== false`-gate the badge.
  - R2 — `createStream` signature drift: mitigated by post-assignment in route (§1a);
    if H8's `createStream` later takes `continuous`, route assignment becomes redundant
    but harmless — converge then, not now.
  - R3 — Status-string coupling in e2e (em-dash `—`): assert via regex `/continuous — Stop to end/`
    to tolerate spacing, and keep badge text assertion independent.
  - R4 — Type drift (`discovery` `continuous: boolean` vs control `continuous?: boolean`):
    intentional and documented (persisted-new vs wire-tolerant); do not "fix" by making
    control required until a migration backfills old streams.
