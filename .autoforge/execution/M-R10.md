- All other M-R10 behaviors are already in place in the repo:
  - KV-first loadDedupeIndexAsync with a KV-first attempt, falling back to file seed via loadDedupeIndex
  - In-file write guarded by a serialized writeQueue to avoid forks and race conditions
  - EROFS/ENOENT warnings emitted when trying to seed the file mirror (KV-truth remains the source of truth)
  - Global shim for __KV_DEDUPE_INDEX__ to enable fast in-process KV reads

## Rationale aligned with plan
- Smallest correct change: centralize path usage to DEDUPE_INDEX_PATH; no behavioral changes beyond a tiny refactor.
- Maintains KV-first approach as the primary source of truth, with graceful fallback to file seed when KV is unavailable.
- Write queue guarantees single-writer semantics for the dedupe index file.
