## Algorithm as implemented (plan M2.2)

- **Regions.** `B = text.normalize("NFC").slice(0, scan.chars)` (v2: NFC + 1 000 000; v1 declares no
  normalisation, so v1 stays byte-faithful to the live harvester), `truncated = body.length > cap`,
  `text_chars_scanned = B.length`; `T = title.normalize("NFC")`. `body_available = B.length > 0`.
- **Scope.** `text` ⇒ B only, `title` ⇒ T only, `any` ⇒ B and T, scanned independently. A `scope:"any"`
  rule matching in both regions contributes its stage **once**, and the **title** match wins.
- **Provenance.** every match carries `evidence_scope` (`body`/`title`) and the char `offset` inside
  its region.
- **Tiers (D11).** tier-1 rules decide; tier-2 (ambiguity) rules run only when tier 1 produced zero
  stages; an asset rule (`asset_type`, no stage) never yields a stage and never affects stage/cell.
- **Confidence (D1).** `candidates.length >= 2` ⇒ `inferred`; a no-cell bucket (`PRE_OPENING`,
  `EXISTING`, `CONSTRUCTION` — cells map to `""`) ⇒ `inferred` (D12 is unconditional); a derived rule
  ⇒ `interpreted`; a named rule with a canonical cell ⇒ `authoritative`; a **bare stage ordinal**
  (`"Stage 1"`, `"Stage 3"`) ⇒ `interpreted` — D1's own parenthetical example ("bare `Stage 2`").
  Document confidence = the weakest candidate; `null` with no candidate.
- **Decision.** `ambiguous = candidates.length >= 2` ⇒ `cell_key ""` and `stage "MULTI_STAGE"` (the
  committed v1 token, cell `""` in the manifest); one candidate ⇒ its stage and cell; no candidate ⇒ the
  hint, `source "hint"`, `confidence null`, `candidates []`.
- **`scope_basis`** = `taxonomy_reference` when ≥3 distinct stage candidates **and** zero hits in the
  document's own subject/title region (subject region re-implemented: `SUBJECT`/`TITLE`/`RE` line of the
  first 600 chars, else the first 600 chars) — else `own_scope`.
- **Ordering.** candidates sorted by tier asc, then rule declaration order, then stage name ASCII.
- **v1.** the same code path reproduces the live semantics: scan `B.slice(0, 8000)`, >1 distinct stage ⇒
  `MULTI_STAGE`, 1 ⇒ that stage, 0 ⇒ hint (`source "hint"`, `confidence null`).

committed PDF** (`unpdf`, at test time, NFC + whitespace-collapsed, case-insensitive — the attested
phrases appear in the PDFs in caps, e.g. `Planning Stage`), and a `corpus` phrase must occur in the
**committed manifest row** (`docs/RSA-Documents/canada-intake-manifest.jsonl`). The three ticket-declared
rules assert `kind:"ticket-declared"` + `attested:false` — never an attestation. No test touches the
network. The three slow PDFs (ON 8.7 MB, QC 5.5 MB, UNB 3.5 MB) are extracted **once per test file** in a
memoised `describe("reference-PDF attestation (slow)")` block with a 120 000 ms `beforeAll` timeout; the
four small PDFs are extracted in the ordinary test body (also memoised).

## Findings / defects to route back

1. **M1 (rule data) — a rule-level `confidence_form` cannot express the plan's "bare stage" reading.**
   Plan M2.3 rows 2 and 5 expect `interpreted` for a corpus title `Stage 1 …` / `Stage 3 …`, but M1
   gives `CA-FEAS` and `CA-DETAIL` the rule-level `confidence_form:"named"`, and D1 (M2.2 step 4) makes
   "named + a canonical cell" ⇒ `authoritative`. The two plan sentences are only compatible if a bare
   stage ordinal is *not* a named stage. I implemented D1's own parenthetical example as a narrow
   refinement (a matched phrase that is a bare stage ordinal is `interpreted`, never `authoritative`) —
   that is what makes rows 2 and 5 pass. **Recommended M1 fix:** split the confidence per alternative
   (`stage N` ⇒ `derived`), so the classifier needs no special case.
2. **M1 (rule data) — `CA-AMBIG-AVP` is unreachable in a body.** `CA-PRELIM-FR` (tier 1, scope `text`)
   carries a superset of the same pattern, so D11 always resolves the phrase in a body to a single
   `PRELIMINARY_DESIGN`; the tier-2 rule only fires when the phrase is **title-scoped** (test 16 proves
   that path). Either drop `CA-AMBIG-AVP` or narrow `CA-PRELIM-FR`.
3. **M1 (rule data) — `CA-ASSET` is title-scoped but broad.** `station|corridor|functional\s+design`
   sets `asset_type:"station"` for any title containing the word "station" (e.g. "Station Road Study"),
   not only for a transit station. D10 is respected (metadata only, never a stage/cell), but the cue is
   loose.
4. **M1 (rule data) — `CA-CONSTR`'s `travaux` alternative is wide**: any French document containing
   "travaux" classifies as `CONSTRUCTION`. It is the MTQ term, but it is a single common noun.
5. **Plan/spec notes (not defects, recorded for M3/M5):**
   - `CANONICAL_STAGE` is **not exported** from `scripts/harvest-track-a.ts`, so test 19 parses the
     literal out of the source file (the same mechanical approach as the regex literals) instead of
     importing it. D13 forbids touching that file.
   - The type sketch's `offset: -1 for hint` is unreachable: a hint never produces a candidate (D1:
     `confidence null`, `candidates []`), so every candidate offset is a real region offset.
   - A v2 ambiguous decision reports `stage:"MULTI_STAGE"` (the committed token, cell `""` in the
     manifest) rather than `UNSTAGED`; the plan's type sketch calls it "a v1-only token", so M5 should
     confirm that reading before the coverage table is written.
   - Phrase attestation in the tests is case-insensitive and whitespace-collapsed: the attested phrases
     exist in the PDFs in caps (`Planning Stage`, `Pre-opening Stage`).
