## 3. Decisions taken inside M3 (and why)

1. **The v1 hint is the neutral `UNSTAGED`.** The v1 column is the v1 *rule file's* verdict recomputed over the same text.
   Borrowing the committed manifest stage as the hint would make the comparison circular (the "recomputed" column would
   always agree), and a per-source hint would add an input the plan's CLI surface does not declare. So every row the text
   does not decide falls back to `UNSTAGED` and is reported as `v1_agreement: "disagree"` — a finding, never reconciled.
   With the corpus present (M4) the text-hit rows agree; with an empty cache (this module's run) all 33 rows are title-only,
   so the v1 recomputation has nothing to scan and 27 rows disagree — the md labels that explicitly ("a missing corpus,
   not a classifier finding").
2. **"moved" is cell-level, v1 committed → v2** (`cell_key_v1_committed !== cell_key_v2`). The recomputed v1 verdict is shown
   beside it in §4 so a hint-driven difference is never confused with a rule-set change.
3. **`coverage_candidate` is not an exported function.** It is a field computed inside `mergeRows`
   (`scripts/harvest-track-a-report.ts:288-299`). The "before have" column therefore uses that field **unmodified**; the
   "after have" column re-applies the *identical* predicate to the row's **effective** cell under v2 (Canadian ∧ T3/T4 ∧
   cell ≠ null ∧ `klass === "rsa-sample"` ∧ not a duplicate ∧ licence not `BLOCKED`). `scripts/harvest-track-a-report.ts`
   was imported, never edited.
4. **The sidecar's `source` is `"title"` for every title-only row** (plan M5.1 acceptance: `body_available:false` ⇔
   `source:"title"`). The classifier itself reports `"hint"` for a row with no candidate at all; the sidecar overrides it so
   the invariant holds. A row *with* a body keeps the classifier's own source.
5. **The json's `rows[]` carries the plan's M5.1 sidecar fields** (not the shorthand `v1_committed` / `v2_cell` names of the
   M5.2 sketch), so one row shape serves the sidecar, the movement table and the ambiguity table.
6. **The `fetch` budget counts every byte spent** (including a sha-mismatched row) against `--max-total-bytes`; the
   per-file cap aborts mid-stream, deletes the `.part` and reports `unavailable (oversize)`.

  `docs/RSA-Documents/canada-intake-manifest.jsonl` (33 rows), `licence` = `parseLicenceRegister(LICENSE-REGISTER.md)`.
* `merged.length = 335` (304 inventory + 33 manifest − 2 shas present in both).
* `merged.filter(r => r.coverage_candidate)` = **2**: `a24707c6081a…` (inventory-only, ON, T3, `stage:"detailed"` →
  `canada:DETAILED_DESIGN`, licence `RESTRICTED`) and `0af7ea584ae0…` (manifest row 1, AB, T3 →
  `canada:FEASIBILITY_CONCEPT`, licence `CLEAR`) ⇒ the committed round-2 "after have" **1 / 0 / 1**, reproduced by the
  "before have" column of Table B.
* `merged.filter(r => r.canadian).length` = 156; `merged.filter(r => r.canadian && (tier === "T3" || "T4")).length` = 32.
* Table A's committed cell occupancy = **10 / 3 / 20** (`canada:FEASIBILITY_CONCEPT` 10, `canada:PRELIMINARY_DESIGN` 3,

## 6. Deviations from the plan (explicit)

1. **`--dry-run` added to `fetch`** (the brief authorised it): the fetch path is proven without a request. Every other flag
   and default is exactly the plan's.
2. **The hint used for the v1 recomputation is `UNSTAGED`** — the plan does not specify one; see §3.1.
3. **The json's `rows[]` uses the M5.1 sidecar field names** rather than the M5.2 sketch's shorthand, so the sidecar, the
   movement table and the ambiguity list share one row shape (§3.5).
4. **`coverage_candidate` had to be re-applied by hand for the "after have" column** because it is not exported as a
   standalone predicate; the "before have" column uses `mergeRows`' own unmodified field (§3.3).
5. **The §5 of the coverage md is the ambiguity *table*** (the same rows as `ambiguous-v2.md`, which carries the header and
   the notes) — the two cannot be byte-equal because `ambiguous-v2.md` is a standalone document.
6. **The `fetch` summary prints hosts and URLs** on stdout. That is a run report, not one of the four committed artefacts;
   the artefacts carry no hostname.
