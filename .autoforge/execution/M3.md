# M3 — harvester round-2 support

**Files changed**: `scripts/harvest-track-a.ts`, `scripts/harvest-track-a-report.ts`.

## Changes

1. **A `candidate-list` strategy.** `Source.strategy` gained the value
   (`scripts/harvest-track-a.ts:63-95`). `candidatesFor` returns the committed candidate rows for
   that source (`scripts/harvest-track-a.ts:307-313`), so discovery stays separate from fetching
   and the committed candidate list is the auditable record. `enumerateSource` is exported so the
   round-2 discovery script runs the same robots-checked listing strategies.
2. **Per-candidate attributes.** `CandidateRow` and `candidateRows()` carry the licence, the
   province hint, the stage hint and the document-type hint of each candidate, because one search
   returns candidates from many hosts. `attributesFor()` resolves them, falling back to the
   source's declared defaults.
3. **The 5 GB cap, enforced before the write.** `corpusBytes()` measures the bytes the corpus
   already holds (the intake manifest's byte column plus the download log). `BYTE_CAP_BYTES` is
   5 GiB and `PER_DOCUMENT_CAP_BYTES` is 100 MiB. A candidate whose declared `Content-Length`
   exceeds `min(remaining, 100 MiB)` is refused with reason `byte-cap`; after the body is read the
   same check runs again before `writeFileSync`, so a document is never written past the cap. The
   accounting is written to `docs/RSA-Documents/track-a-round2-bytes.json`.
4. **A write failure no longer aborts the round** — it is skipped with reason `write error`
   (found during this run: a shared disk hit ENOSPC mid-round).
5. **Additive manifest fields.** `round`, `stage_source` and `tier_source`. `detectStageWithSource`
   and `detectTierWithSource` report where the value came from (`text` or `hint` /
   `doc_type_hint`); `detectStage` and `detectTier` keep their old signatures and behaviour.
6. **French stage vocabulary.** `STAGE_RULES` now also matches `préliminaire`, `détaillé`,
   `avant ouverture`, `en service`, `planification` and `étude de faisabilité`, so a French RSA no
   longer falls silently into `UNSTAGED` (the ticket's rule set is unchanged; the vocabulary is
   what was missing).
7. **The candidate log.** `docs/RSA-Documents/track-a-round2-candidate-log.tsv` — one row per
   candidate examined, with the HTTP status, the byte count, the sha256, the decision, the reason,
   the dedupe status and the stage/tier provenance.
8. **A licence register row per source *attempted*.** Before, a row was written only for a source
   that contributed a document; now a source that was attempted gets a row even when it yielded
   nothing, and the verdict is the most restrictive among the documents its directory holds.
9. **The round filter in the round-1 report generator.** `scripts/harvest-track-a-report.ts` reads
   only the manifest rows whose `round` is not `"2"`, so the committed round-1 report stays
   byte-identical and its vitest guard stays green without regenerating a historical artefact.

## Acceptance

- The round-1 report is byte-unchanged — verified: `git diff --exit-code -- docs/RSA-Documents/track-a-harvest-report.md` is clean after the round-2 rows were appended.
- The candidate log has exactly one row per candidate examined — verified by the round-2 test.
- No byte is written past the cap — the cap is checked twice, before the body and before the write.
