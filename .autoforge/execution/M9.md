# M9 — explicit tenant-store cutover gate (PR #59, ticket #53)

## What changed

The Postgres tenant path is now an EXPLICIT operator cutover instead of a
side effect of `POSTGRES_URL`. Production already carries a platform-injected
owner-role `POSTGRES_URL` (Vercel-Supabase link, no tenant tables), so a path
keyed off it took the tenant branch at merge time and every request failed on
the pool factory's owner-role refusal.

- `src/lib/db/config.ts:23` — new `tenantStoreEnabled()` (the cutover switch:
  `TENANT_STORE=postgres`); `isDatabaseConfigured()` = switch AND url;
  `postgresUrl()` reads `TENANT_POSTGRES_URL`, NEVER `POSTGRES_URL`;
  `isTestEnv()` kept for `postgresUrlNonPooling()` only.
- `src/lib/db/pg-client.ts:108` — `createPgPool()` refuses in `NODE_ENV=test`
  (the offline guarantee moved out of config.ts so the gate stays testable);
  messages now name `TENANT_POSTGRES_URL`.
- `src/lib/db/identity.ts` — comments only (the gate name).
- `scripts/migrate-kv-to-postgres.ts` — the migration target is
  `TENANT_POSTGRES_URL`.
- `vitest.config.ts` — offline env block extended.
- `.env.example` — `TENANT_STORE=` + `TENANT_POSTGRES_URL=` added;
  `POSTGRES_URL` annotated as the platform-injected owner url the app does
  not use. No values.
- `supabase/README.md`, `docs/deployment.md`,
  `docs/compliance/sub-processor-register.md`, `docs/decisions/log.md` — the
  operator cutover order (0001->0002->0003, password out of band,
  `TENANT_POSTGRES_URL`, KV migration dry-run+apply, `TENANT_STORE=postgres`
  LAST) and why the switch exists.
- `tests/integration/tenant-store-cutover.test.ts` — new, offline: (a)
  `POSTGRES_URL` set + `TENANT_STORE` unset keeps the Upstash path
  (`database_state: "legacy"`, `code: "database_not_configured"`), (b)
  switch + `TENANT_POSTGRES_URL` -> gate on, (c) switch without the url ->
  legacy, (d) config.ts never reads `POSTGRES_URL`.

## Notes / risks

- The design of the PR (forced RLS, server-side claims under the app role,
  membership check, owner/service_role refusal) is unchanged.
- `DB_ALLOW_OWNER=1` remains the out-of-band escape hatch; it is now about
  `TENANT_POSTGRES_URL`.
- The app role's password is never in the repo: the operator generates it and
  runs `alter role auditorai_app password ...` out of band.
