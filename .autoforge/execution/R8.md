Module: health-aggregate + health route wiring (R8)

- What I built:
  - A pure aggregator: src/discovery/health-aggregate.ts with function aggregateHarvestHealth(entries?) -> HarvestHealth { lastRunAt, lastSuccessAt, lastHits, degraded }.
  - A lightweight in-process single-writer lock: src/lib/persistence/single-writer.ts to guard persistence paths (hazard: src/lib/persistence/**).
  - Expanded health route: src/app/api/dev/health/route.ts now exposes harvestHealth as a sub-object derived from the discovery ledger via the new aggregator. It uses the single-writer wrapper to guard reads of state/discovery-ledger.json and persists no state itself.
  - A small unit test for the aggregator: src/discovery/__tests__/health-aggregate.test.ts which validates lastRunAt, lastHits, lastSuccessAt and degraded behavior.

- Important notes:
  - The aggregator is pure and side-effect-free; it only derives a snapshot from LedgerEntry[] shape.
  - The route returns harvestHealth with fields possibly null when the ledger is unavailable, matching the contract requirement.
  - No new external dependencies were added; everything is implemented with existing stdlib and repo conventions.

- How to verify:
  - Run tests: npm test or pnpm test (Vitest) depending on repo setup.
  - Hit GET /api/dev/health and observe harvestHealth in the response.
