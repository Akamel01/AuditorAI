## Checks you must make

1. **Recompute the numbers yourself** from the committed inputs (a short python/awk script in /tmp
   is fine) and compare them with the report. Every number in the report must be traceable to a
   committed file. Flag any number you cannot reproduce.
2. **RC-1 (coverage-candidate rule).** An inventory row counts only when it is Canadian, tier T3/T4
   and stage-mapped, and `class == "rsa-sample"`; a manifest row counts on tier + cell_key alone
   (it has no `class` field). T1 appears in no cell count. A sha256 present in BOTH sources is
   counted ONCE and attributed to the fetched column — verify the committed case (sha `0af7ea58…`,
   manifest row 1 T3 `canada:FEASIBILITY_CONCEPT` vs inventory row 231 `planning`/T0).
3. **RC-2 (denominators).** The two row sets |A| (all rows) and |B| (Canadian subset) are stated
   explicitly and never mixed; `out-of-scope` appears only in |A| and its absence from |B| is
   stated. Every class value present in the inventory appears in the all-rows table.
4. **RC-4 (no hard-coded counts).** The fetched-only section lists EVERY manifest row, derived
   from the file, not from a constant.
5. **Stage mapping.** `planning`/`preliminary`/`detailed` map to the three Canadian cells;
   `existing`, `pre-opening` and `unknown` are reported as unmapped with their counts. Check the
   mapping against `state/odd-coverage.json` and `policies/canada/pack.json`.
6. **Reproducibility.** The report contains no timestamp and is regenerated byte-identically by
   `npx tsx scripts/harvest-track-a-report.ts` (you may run it and `git diff --exit-code`).
7. **Containment.** No network call, no model/LLM call; the script writes only the report file;
   `main()` is guarded so importing it in the test does not run the CLI.
8. **The cross-check.** The inventory-only Canadian subset must reproduce
   `docs/RSA-Documents/track-a-ondisk-summary.json:64-92`.
9. **The unfillable section** lists all 13 families and every Canadian cell with a zero count.
10. **Test quality.** The 20 tests must be offline and must fail if the counting rule is broken;
    flag vacuous assertions.
