# Findings

### MAJOR-1 — `CA-PRELIM-FR` carries an unsanctioned bare-word alternative that is a new false-positive family — `stage-rules.v2.json:333`

`"pattern": "avant-projet\\s+pr[ée]liminaire|plans\\s+et\\s+devis\\s+pr[ée]liminaires|pr[ée]liminaire"`

The third alternative `pr[ée]liminaire` is **not** in the plan's pattern intent for this rule
(`plan-t62.md:151` lists only `avant-projet préliminaire`, `plans et devis préliminaires`) and has **no**
evidence entry attesting the bare word. It is a tier-1 named-stage rule, so it produces an
`authoritative`-shaped `PRELIMINARY_DESIGN` candidate **with the cell `canada:PRELIMINARY_DESIGN`** for
any French text that merely contains the word:

```
CA-PRELIM-FR       MATCH  "préliminaire"
CA-PRELIM-FR       MATCH  "rapport préliminaire de l'audit"
CA-PRELIM-FR       MATCH  "l'étude préliminaire du projet"
CA-PRELIM-FR       MATCH  "phase préliminaire"
CA-PRELIM-FR       MATCH  "preliminaire"
```

That is exactly the class of defect ticket #62 exists to remove (v1's `mise en service` → `PRE_OPENING`).
It also makes `CA-PRELIM-TICKET` (`conception préliminaire`, `stage-rules.v2.json:496`) redundant —
`CA-PRELIM-FR` matches its phrase:
`CA-PRELIM-FR (tier1) also matches CA-PRELIM-TICKET evidence phrase "conception préliminaire"`.
Required change: drop the bare `pr[ée]liminaire` alternative from `CA-PRELIM-FR` (the ticket term is
already covered by `CA-PRELIM-TICKET`; the MTQ terms by the two attested phrases).

### MAJOR-2 — `CA-AMBIG-AVP` can never produce the ambiguity it exists for — `stage-rules.v2.json:333` vs `:453`

`CA-AMBIG-AVP` (`"avant-projet\\s+pr[ée]liminaire"`, tier 2, scope `any`) has **the same trigger** as the
tier-1 `CA-PRELIM-FR` alternative `avant-projet\s+pr[ée]liminaire`. Under the plan's own classifier
algorithm (`plan-t62.md:227-228`: "run Tier-1 rules … If Tier 1 produced zero stages, run Tier-2 rules"),
tier 1 always wins, so the tier-2 rule is unreachable for any document that has body text:

```
CA-AMBIG-AVP: sample "avant-projet préliminaire" -> tier1 fires: CA-PRELIM-FR
```

It can only fire on a **title-only** row (`CA-PRELIM-FR` is `scope:"text"`, i.e. body-only). The French
AVP ambiguity — one of the four ambiguity cases the ticket asks for — is therefore unreachable in the
normal case. (The plan's rule table contradicts itself here: `plan-t62.md:151` gives the phrase to
`CA-PRELIM-FR` and `plan-t62.md:156` gives the same phrase to `CA-AMBIG-AVP`; the shipped JSON inherits
the contradiction. M1 owns the JSON, so it must be resolved there.)
Required change: make the two triggers disjoint. Recommended: `CA-AMBIG-AVP` owns
`avant-projet\s+pr[ée]liminaire` (its evidence entry already cites that QC phrase, attested), and
`CA-PRELIM-FR` keeps only `plans\s+et\s+devis\s+pr[ée]liminaires` — dropping its
`avant-projet préliminaire` alternative **and** its matching evidence entry (an evidence entry whose
phrase the rule's own pattern no longer matches would break M2's per-rule test). Whichever assignment
is chosen, record it in the file-level `note` and get the plan amended.

### MAJOR-3 — `CA-EXISTING` cannot match the attested spaced spelling "in service <noun>" — `stage-rules.v2.json:243`

`"pattern": "in-?service\\s+(?:road|highway|corridor|facilit|review|audit)|existing\\s+(?:road|highway|corridor|facilit)|post-?opening|already\\s+in\\s+service|apr[èe]s\\s+ouverture"`

`in-?service` matches `inservice` / `in-service`, **not** `in service` (a space). The spaced form is the
one attested in the committed reference set:

```
-- pattern match for space variants --
CA-EXISTING    "post opening"     NO MATCH
CA-EXISTING    "in service"       NO MATCH
CA-EXISTING    "in-service"       NO MATCH
CA-EXISTING    "post-opening"     MATCH

-- do these phrases occur in the committed PDFs --
"in service"   alberta-transportation-rsa-implementation-plan-2004, ontario-good-roads-rsa-guideline-2023, unb-transportation-group-rsa-guidelines
```

("in service" is listed as attested evidence for the AB impl-plan, ON and UNB documents in the plan's own
table, `plan-t62.md:67,70,72`.) The same `-?` slip affects `post-?opening` ("post opening" — not
attested today, but the same class). Impact on the 33-row corpus is nil today (no manifest title uses
the spaced form), but the rule is a headline bucket (EXISTING = 22 of the 32 Canadian T3/T4 documents).
Required change: `in[\s-]?service\s+(?:road|highway|corridor|facilit|review|audit)` and
`post[\s-]?opening`.

### MINOR-1 — `CA-DETAIL-FR` carries v1's leftover French regex, unsanctioned and half-broken — `stage-rules.v2.json:357`

`"pattern": "plans\\s+et\\s+devis\\s+d[ée]finitifs|avant-projet\\s+d[ée]finitif|d[ée]taill[ée]e?\\b"`

The third alternative is v1's `/d[ée]taill[ée]e?\b/i` (`scripts/harvest-track-a.ts:518`) and is not in

the ordinary French `détail` / `détails` (`CA-DETAIL-FR "détail" → no`, `"détails" → no`), and it has no

(`CA-DETAIL-FR (tier1) also matches CA-DETAIL-TICKET evidence phrase "conception détaillée"`), making
`CA-DETAIL-TICKET` (`stage-rules.v2.json:521`) redundant.
Required change: drop the leftover alternative (the QC phrases are attested and sufficient), or — if a
generic French "détaillé" cue is wanted — replace it with `d[ée]taill[ée]s?\b` and add an evidence entry.
