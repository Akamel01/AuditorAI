## Verdict

**CHANGES_REQUIRED** — no blocker. The gate and docs are correct and the production
failure mode is gone, but the test does not pin the switch itself: an implementation
with `TENANT_STORE` deleted from `isDatabaseConfigured()` passes all four cases.

## Blockers

None.

## Major

**M1 — the test cannot fail if the switch is removed.**
`tests/integration/tenant-store-cutover.test.ts:58-114`.
Mutate `src/lib/db/config.ts:35-37` to `return postgresUrl() !== null` (drop
`tenantStoreEnabled()`) and all four cases still pass:
(a) leaves `TENANT_POSTGRES_URL` unset, so it is false either way;
(b) sets both, so it is true either way; (c) sets the switch but no URL, so it is
false either way; (d) only scans source text.
So the contract "Postgres ONLY when `TENANT_STORE=postgres`" is unverified, including
the realistic partial-cutover state (operator has set `TENANT_POSTGRES_URL` at step 3
but has not flipped the switch at step 5).
Note: case (a) *does* fail if `config.ts` reads `POSTGRES_URL` again — with
`POSTGRES_URL=OWNER_URL` the gate opens, `createPgPool` refuses in `NODE_ENV=test`
(pg-client.ts:108-116), and the POST is not 201. It is not vacuous, just incomplete.
Minimal fix: add a fifth case — set `TENANT_POSTGRES_URL = APP_URL`, leave
`TENANT_STORE` unset, assert `tenantStoreEnabled() === false` and
`isDatabaseConfigured() === false` (a GET asserting `legacy` /
`database_not_configured` is optional). That case fails against the mutated
implementation.

## Minor

- **m1 — source-text assertion is a tripwire only.**
  `tests/integration/tenant-store-cutover.test.ts:110-114`. It matches the literal
  `env("POSTGRES_URL")`; a direct `process.env.POSTGRES_URL` read or an alias would
  pass. Acceptable as a second layer, not as the proof of the gate (see M1).
- **m2 — unreconciled decision-log rationale.**
  `docs/decisions/log.md:8` says "an env switch would serve Production from an empty
  database on the first deploy", while `:9` adds an env switch (correctly, as a global
  safety gate on top of the per-workspace credential-row cutover). Fix: add that
  relationship clause to the 2026-10-22 entry rather than editing history.
- **m3 — latent bypass outside the request path.**
  `src/lib/db/credentials.ts:64,101` call `tenantSqlClient()` without
  `isTenantDatabaseAvailable()`. With `TENANT_STORE` unset but `TENANT_POSTGRES_URL`
  set, revoke/rotate would build a pool and run. Currently unreachable (no callers in
  `src/`, `scripts/`, `tests/`) and it never reads `POSTGRES_URL`, so it is not a
  regression — note only.
- **m4 — stale "must" in the compliance register.**
  `docs/compliance/sub-processor-register.md:90-93` still requires ACTION-1 "before
  the merge reaches Production", while `docs/deployment.md:44-49` says the merge is
  safe by construction. Not contradictory (doing it first is a superset), but the
  "must" is now over-stated.
