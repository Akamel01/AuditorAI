## 7. Findings (each with evidence and a fix)

**F1 — MAJOR — an unrelated curated file is committed empty (foreign-lane artefact staged by mistake).**
`.autoforge/state.json` is **0 bytes** at HEAD (`git cat-file -s oc/60:.autoforge/state.json` → 0); `origin/main` has 12,591 bytes; commit `dc13b8d` deletes all 67 lines. The file is listed as *curated and committed for traceability* in `.autoforge/AGENTS.md:5-7`, and the round-1 lane identified exactly this file as a **foreign-lane modification that must not be staged** (`.autoforge/execution/M7.md:92-99`, `.autoforge/execution/M7b.md:220-224`). Nothing in the PR body mentions it.
*Fix:* `git checkout origin/main -- .autoforge/state.json` (or rewrite it as the #60 state) and note it in the PR body.

**F2 — MODERATE — the "before" column cites no base commit (R6 / R44 / D3 unmet).**
R6 requires the report to "cite the base commit sha" (`.autoforge/requirements/grilling.md:71-73`), R44 repeats it (`:258-262`), and D3's own stated consequence is that the report "prints both inline **with the base commit sha**" (`.autoforge/architecture/decisions.md:74-76`). The report cites none (no hex sha of length ≥7 in the file); `report:33` defines "before" only as "the manifest rows without `round: \"2\"`".
*Fix:* add a `const BASE_COMMIT = "<sha of origin/main>";` constant to `scripts/harvest-track-a-round2-report.ts` and print it once in §1 ("before = the corpus at `<sha>`"), then regenerate — deterministic, no live `git rev-parse`.

**F3 — MODERATE — the PR body overstates what the "before" test guarantees.**
PR body: "the 'before' column is asserted against the round-1 numbers in `tests/discovery/harvest-track-a-round2-report.test.ts`". That test (`tests/discovery/harvest-track-a-round2-report.test.ts:144-159`) re-derives the before column from the *same* generator inputs via `mergeRows()` and compares it to the report — it never reads the committed round-1 report nor pins 1/0/1, so a `mergeRows` regression moves both sides together. The numbers themselves are correct (I verified 1/0/1 against the round-1 report in `origin/main`).
*Fix:* pin the literals (`expect(cells[4]).toBe("1" | "0" | "1")`) or compare against the committed round-1 report's table.

**F4 — MINOR — the 6 non-Canadian T3/T4 documents are said to be "counted as out-of-scope in the funnel", but they are not.**
`report:53` and the PR body both say so; in §2c they sit in the row `rsa-sample (ingested, T3/T4 — not Canadian, or stage unmapped)` (= 8, of which 6 non-Canadian + 2 Canadian unmapped), while `out-of-scope` = 39 counts only `reason == "not RSA"` (`report:97`, `:110`). R13's class definition is "out-of-scope (fetched but rejected by the RSA classifier **or non-Canadian**)", so the 21 non-Canadian ingested rows are also outside R13's class.
*Fix:* either reword to "are counted in the funnel's *not Canadian* branch", or move non-Canadian ingested rows into the `out-of-scope` row to match R13.

**F5 — MINOR — §5 mislabels bytes written as bytes downloaded.**
`report:186`: "51177492 bytes were downloaded". That figure is bytes **written to the shelf** (`downloaded_this_round` in `track-a-round2-bytes.json`); **139,419,291** bytes went over the wire and 88,241,799 were discarded by the known-hash gate. The byte file distinguishes them; the report prose does not (the PR body does).
*Fix:* print `fetched_this_round` and `discarded_bytes` too and label 51,177,492 as "written to the shelf".

**F6 — MINOR — "hosts tried" counts hosts that produced a URL, not hosts tried.**
`scripts/harvest-track-a-round2-report.ts:468` derives the column from the candidates' hosts. The hosts the round actually tried and lost (`www.quebec.ca`, `pub-ottawa.escribemeetings.com`, `www.toronto.ca`, `open.saskatchewan.ca`, `data.gov.mb.ca`, `www.muniac.ca`) never appear, so the gap table's "re-attempted" claims have no numeric counterpart (R19/R20).
*Fix:* derive the cell from the source list + the log and name the unreachable hosts and their failure reason.

**F7 — MINOR — the French stage rules added in this round have no unit test.**
`scripts/harvest-track-a.ts:516-521` adds `pr[ée]liminaire`, `d[ée]taill[ée]e?`, `avant ouverture`, `en service`, `planification`, `[ée]tude de faisabilit[ée]`; no test in `tests/` matches a French pattern (grep: 0). The disclosure in §5 (`report:193-195`) is in place and the before/after comparison is unaffected (the affected row is T1), but the guard requested by the earlier review is absent.
*Fix:* one `detectStageWithSource` case per French pattern in `tests/discovery/harvest-track-a.test.ts`.

**F8 — MINOR — every round-2 source entry's `host` is the discovery host, not the document host.**
`docs/RSA-Documents/track-a-round2-sources.json:65,104,137,173,205,249,287` all carry `"host": "html.duckduckgo.com"` while the 108 candidates come from 41 other hosts. The `discovery` block now documents the channel honestly, so nothing downstream is misled (the report's "hosts tried" comes from the URLs, not this field), but the field itself is ambiguous.
*Fix:* set `host` to the document host per source, or add `discovery_host` and say which is which.

**F9 — INFO — `npx vitest run` dirties a tracked file.**
`src/discovery/harvest.ts:281` writes `state/production-harvest-proof.json` during tests, so a test run leaves the worktree dirty (I restored it to HEAD). Pre-existing behaviour, not introduced by this PR, but it will trip the pre-commit hook / any `git diff --exit-code` gate.
