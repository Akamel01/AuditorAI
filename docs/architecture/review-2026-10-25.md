## Deepening opportunities (ranked, best first)

### 1. Mission-control client wrappers → one typed endpoint map (Strong, M)

- Files: `src/lib/client.ts:108-195` (20+ `fetchX` one-liners over `adminApi`), `src/app/dev/mission-control/page.tsx`.
- Problem: each dev surface is a shallow wrapper whose interface (name + return) is as complex as its body (`adminApi<T>("/api/dev/…")`). Understanding one concept (a dev read) requires bouncing between wrapper and route; nothing concentrates; tests exercise `adminApi`, not the wrappers.
- Proposed change: replace the 20 wrappers with a single `devApi` keyed by a small endpoint enum/record, so adding a surface is a data entry, not a new function. Keep `adminApi`/`send` as the seam.
- Effect: locality — endpoint paths live in one place; tests assert the map, not N functions. Behaviour-preserving (covered by e2e `harvest-buttons.spec.ts`).
- Size: M.
