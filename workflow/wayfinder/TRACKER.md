# Wayfinding operations — this repo's tracker

No external tracker is configured, so Wayfinder uses a **local-markdown tracker**
committed to the repository. Git is part of shared state; any session can reconstruct
the frontier from these files alone.

## Trackers

- **mvp map**: local-markdown only (below).
- **v2-agentic-platform map**: canonical on **GitHub Issues** — map issue #20, child issues #1–#19
  (labels `wayfinder:*`, `ready-for-agent`, `blocked`, `hitl`). Local `tickets/*.md` mirror each issue
  via an `issue:` front-matter line; resolutions are posted as issue comments AND appended locally.

- **ops-residual / ops-seamless-verify maps**: local-markdown only.
- **Index**: `src/wayfinder/tickets.ts` compiles every `tickets/*.md` for Mission Control
  (`/dev/mission-control` → Tickets) and `npm run tickets`. Markdown remains canonical;
  claim/resolve still happens by editing front-matter.

## Layout

```text
workflow/wayfinder/
  TRACKER.md                  ← this file (conventions)
  maps/<slug>/
    MAP.md                    ← the map: Destination / Notes / Decisions so far /
                                Not yet specified / Out of scope
    tickets/<ID>-<slug>.md    ← one file per decision ticket
```

## Ticket file format

```markdown
---
id: R1
title: Short name used in narration
type: research | prototype | grilling | task
hitl: true | false          # HITL tickets resolve only with the human
status: open | claimed | closed | out-of-scope
assignee:                   # set on claim; an assigned open ticket is claimed
blocked_by: [R1, R2]
blocks: []
created: 2026-08-22
resolved:
---

## Question

<the decision or investigation this ticket resolves>

## Resolution

<appended on resolution; assets linked, not pasted>
```

## Operations

- **Memory protocol**: every session follows `workflow/vault-protocol.md` — MUST-READ at
  start (CONTEXT.md, MAP.md, latest journal), MUST-WRITE at end (journal entry, gotchas,
  mirror flips). Graduation rules live there too.
- **Frontier**: open + unassigned + every `blocked_by` closed. Work only frontier tickets.
- **Claim**: set `assignee` + `status: claimed` before any work.
- **Resolve**: append `## Resolution`, set `status: closed` (+ `resolved:` date), add one
  index line to the map's *Decisions so far* (name wraps gist; link to ticket).
- **Out of scope**: close with `status: out-of-scope` and one line in the map's
  *Out of scope* section. Never graduates back.
- **Fog**: un-ticketed future decisions live in *Not yet specified*; graduate into fresh
  tickets one at a time when they become sharply phraseable.
- **Never resolve more than one non-research ticket per session**; research tickets may be
  batched to parallel subagents.
- Researchers write **only their own** `docs/research/*.md`; the orchestrator commits and
  compiles registries. Subagents never mutate `state/*.json`.

## Triage (GitHub Issues, v2 map)

Skill: `triage` (mattpocock). Every issue carries one **category** role + one **state** role.
Every tracker comment generated by AI starts with the disclaimer `> *This was generated by AI during triage.*`

### Label mapping

| Canonical role | Label here |
|---|---|
| category: bug / enhancement | `bug` / `enhancement` |
| state: needs-triage | `needs-triage` |
| state: needs-info | `needs-info` |
| state: ready-for-agent | `ready-for-agent` |
| state: ready-for-human | `ready-for-human` |
| state: wontfix | `wontfix` |

Auxiliary (not canonical states): `wayfinder:{map,research,grilling,prototype,task}` type tags;
`hitl` = resolution requires live owner input; `blocked` = dependency-gated pre-state — flips to
`ready-for-agent` when its blockers close. Blocked issues intentionally carry no canonical state yet.

### Deviations from the skill's default machine

- Issue **bodies are the agent briefs** (written in to-spec format at creation); separate brief
  comments are only posted on state *transitions* or incident re-briefs.
- Map issue #20 is exempt from roles (it is an index artifact).
- HITL tickets may sit in `ready-for-agent` when an agent can do all artifact-building and the
  human role is reaction/approval recorded at resolution (#3 D2, #4 V1). Pure owner decisions go
  to `ready-for-human` (#5 R7, #7 E1).

### Incident protocol

Subagent runs claiming completion are verified on disk (`git status --porcelain`, file reads)
before any closure; empty-run/fabrication matches mvp incidents VAL-001/003 → ORCH-direct
execution or hardened single retry.
